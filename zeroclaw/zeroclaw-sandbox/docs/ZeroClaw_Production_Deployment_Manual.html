ZeroClaw 工业级安全分析沙箱 - 生产环境部署手册

1. 前置条件

1.1 硬件要求

  • 最低配置：4核CPU，8GB内存，100GB SSD
  • 推荐配置：8核CPU，16GB内存，500GB SSD
  • 专用物理机或隔离的虚拟机，禁止与生产环境共享资源

1.2 软件要求

  • 操作系统：Ubuntu 22.04 LTS / Debian 12 Bookworm
  • Docker版本：≥25.0.0（推荐最新稳定版）
  • 内核版本：≥5.15（支持Seccomp和AppArmor）
  • 网络：已配置代理，能够访问GitHub

1.3 安全要求

  • 宿主机已禁用所有不必要的服务
  • 已启用防火墙，仅允许必要的入站连接
  • 已禁用root用户直接登录，使用普通用户+sudo
  • 已定期更新系统补丁

2. 安装步骤

2.1 安装Docker（国内网络优化版）

重要提示：由于Docker官方源在国内访问不稳定，以下提供两种国内可用的安装方法

方法一：使用LinuxMirrors一键安装脚本（推荐）

# 一键安装Docker并自动配置国内镜像源
bash <(curl -sSL https://linuxmirrors.cn/docker.sh)

# 将当前用户添加到docker组
sudo usermod -aG docker $USER

# 刷新用户组（无需重新登录）
newgrp docker

# 验证安装
docker --version

方法二：手动安装（使用阿里云镜像源）

# 更新系统
sudo apt-get update && sudo apt-get upgrade -y

# 安装依赖
sudo apt-get install -y ca-certificates curl gnupg lsb-release

# 添加阿里云Docker GPG密钥
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# 添加阿里云Docker仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装Docker
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io

# 将当前用户添加到docker组
sudo usermod -aG docker $USER

# 刷新用户组
newgrp docker

# 验证安装
docker --version

2.2 配置Docker守护进程（含国内镜像加速）

# 创建Docker配置目录
sudo mkdir -p /etc/docker

# 配置用户命名空间隔离、日志驱动和国内镜像加速
echo '{
  "userns-remap": "default",
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  },
  "registry-mirrors": [
    "https://docker.xuanyuan.me",
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com"
  ]
}' | sudo tee /etc/docker/daemon.json

# 重启Docker服务
sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证镜像加速是否生效
docker info | grep -A2 Mirrors

2.3 部署Seccomp安全策略

# 创建Seccomp配置目录
sudo mkdir -p /etc/docker/seccomp

# 复制Seccomp配置文件
sudo cp my-seccomp-profile.json /etc/docker/seccomp/

# 设置正确的权限
sudo chmod 644 /etc/docker/seccomp/my-seccomp-profile.json
sudo chown root:root /etc/docker/seccomp/my-seccomp-profile.json

2.4 安装依赖工具

sudo apt-get install -y tcpdump iptables htop

2.5 构建沙箱镜像

# 克隆或下载部署包到本地
git clone <部署包地址>
cd zeroclaw-sandbox

# 构建镜像（确保已配置代理）
docker build -t zeroclaw-sandbox .

# 验证镜像构建成功
docker images | grep zeroclaw-sandbox

2.6 设置脚本执行权限

chmod +x start-sandbox.sh monitor-traffic.sh

3. 快速验证

3.1 创建测试脚本

mkdir test-skill
echo '#!/bin/bash' > test-skill/test.sh
echo 'echo "Hello from test skill"' >> test-skill/test.sh
echo 'ls -la /' >> test-skill/test.sh
echo 'ping -c 1 8.8.8.8' >> test-skill/test.sh
chmod +x test-skill/test.sh

3.2 启动网络监控

# 在第一个终端执行
./monitor-traffic.sh

3.3 启动沙箱并运行测试

# 在第二个终端执行
./start-sandbox.sh ./test-skill

# 在容器内执行
cd skill
./test.sh

3.4 验证结果

  • 测试脚本应该能够正常执行
  • 应该能够看到ls -la /的输出
  • ping命令应该能够执行
  • 网络监控脚本应该能够捕获到DNS查询和ICMP数据包
  • 检查Seccomp日志：sudo journalctl -k | grep seccomp，不应该有任何被拒绝的系统调用

4. 日常使用指南

4.1 分析可疑Skill

# 启动网络监控
./monitor-traffic.sh

# 在另一个终端启动沙箱
./start-sandbox.sh /path/to/suspicious-skill

# 在容器内进行分析
cd skill
zeroclaw analyze ./suspicious-file

4.2 查看系统调用日志

# 实时查看Seccomp审计日志
sudo journalctl -kf | grep seccomp

# 查看历史日志
sudo journalctl -k --since "1 hour ago" | grep seccomp

4.3 分析网络流量

# 使用Wireshark打开PCAP文件
wireshark analysis-*.pcap

# 或者使用tcpdump分析
tcpdump -r analysis-*.pcap -n

5. 运维指南

5.1 定期更新

# 更新系统
sudo apt-get update && sudo apt-get upgrade -y

# 更新Docker
sudo apt-get update && sudo apt-get upgrade docker-ce docker-ce-cli containerd.io

# 重新构建沙箱镜像（每周一次）
cd zeroclaw-sandbox
docker build --no-cache -t zeroclaw-sandbox .

5.2 日志管理

  • 容器日志：自动轮转，每个文件100MB，最多保留3个
  • 网络流量日志：自动轮转，每个文件100MB，最多保留10个
  • 系统调用日志：由systemd-journald管理，默认保留4周

5.3 资源监控

# 查看容器资源使用情况
docker stats

# 查看宿主机资源使用情况
htop

# 查看磁盘使用情况
df -h

6. 故障排查

6.1 镜像构建失败

  • 检查代理配置是否正确
  • 检查网络连接是否正常
  • 尝试使用--no-cache参数重新构建
  • 验证Docker镜像加速是否生效

6.2 容器无法启动

  • 检查Docker服务是否运行：sudo systemctl status docker
  • 检查Seccomp配置文件路径是否正确
  • 检查资源限制是否过高
  • 查看Docker守护进程日志：sudo journalctl -u docker -f

6.3 网络监控无数据

  • 检查桥接接口名是否正确
  • 检查tcpdump是否有足够的权限
  • 检查容器是否连接到正确的网络
  • 验证防火墙规则是否允许流量捕获

7. 应急响应预案

7.1 容器逃逸疑似事件

  1. 立即停止所有运行中的沙箱容器： 
    docker stop $(docker ps -q --filter name=skill-analysis)
  2. 隔离宿主机，断开网络连接
  3. 保存所有日志和抓包文件： 
    tar -czf incident-$(date +%Y%m%d-%H%M%S).tar.gz /var/log/docker *.pcap
  4. 进行内存取证和磁盘镜像
  5. 重建沙箱环境

7.2 恶意软件爆发

  1. 立即隔离受影响的宿主机
  2. 通知安全团队
  3. 收集所有相关证据
  4. 进行全面的安全评估
  5. 制定并实施修复方案

8. 安全最佳实践

  • 一次一用原则：每次分析都创建一个全新的容器，测试完毕后立即销毁
  • 最小权限原则：仅授予容器必要的权限
  • 定期更新原则：及时更新宿主机、Docker和沙箱镜像
  • 日志审计原则：保留所有操作日志和系统调用日志
  • 隔离原则：将沙箱环境与生产环境完全隔离
